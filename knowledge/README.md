# Website assistant knowledge and RAG

## Architecture and source of truth

The public Next.js site and its database/CMS remain authoritative. `scripts/index-website-knowledge.mjs` follows the public page tree, layouts, and local page imports; it extracts copy, routes, headings, and relationships into generated `index.json`. Curated records are kept alongside generated pages. Admin routes are excluded. `npm run knowledge:index` refreshes the files; `dev` and `build` run it automatically. The manifest tracks page/file counts and SHA-256 source fingerprints.

The source scanner ignores JSX styling/class attributes, resolves only translation keys referenced by each page/component graph, preserves route relationships and per-locale text, and no longer clips a page record at a fixed character limit. Each generated record stores its source routes/files, section headings, and content hash/version. The scan writes `coverage-report.md` and `coverage-report.json`; the JSON report keeps numerical values with their original nearby text, route, section, category, language, and scan version. Duplicate and conflicting-number groups are review candidates and are never silently reconciled.

The chat request also loads current CMS home/trading content, published FAQs, active instruments, and published news. Those live records and the generated page corpus are compared to stored hashes in `knowledge_documents`. Each language version has its own source key, document hash/version, route, title, section, source type, and indexed timestamp. `knowledge_chunks` stores structural text chunks, hashes, ordering, and optional JSON vectors. `knowledge_sync_runs` records document/chunk/embedding counts and status/errors. Chunking favors paragraph and sentence boundaries and uses bounded overlap for long paragraphs. The standard `npm run db:push` Neon HTTP migration creates these three knowledge tables and indexes as well as the existing project tables.

## RAG and multilingual behavior

The endpoint validates and bounds request messages, detects English/French/Arabic from the latest user turn, keeps at most eight recent messages for generation, and retrieves a small grounded context before generation. Retrieval combines page/title/keyword/route scoring, multilingual domain aliases, and (when vectors exist) cosine similarity across indexed languages. Vectors are JSON arrays and cosine ranking currently happens in application code after loading the indexed chunks; this is suitable for the current corpus but is not a PostgreSQL ANN/vector index. AI answers receive the selected content, runtime facts, and security instructions; the static fallback only quotes extracted site text and localized summaries. Unknown facts are explicitly declined. Current account tier pricing/rules, market quotes, and calendar events come from existing server-side database/feed queries, not stale page chunks.

The retrieval vocabulary maps common account, leverage, spread, fee, margin, drawdown, payout, market, instrument, platform, and payment wording across English, French, and Arabic. Dynamic CMS/FAQ/news records retain their actual source language; a missing translation is not fabricated, and the fallback can identify when it is quoting an English source. Active instrument records have explicit English/French/Arabic context and preserve the source unit for spread values (including when the source does not specify one).

The existing widget and `/api/chat` stream protocol are preserved. Arabic direction is controlled by the existing locale-aware chat UI. The language is determined per latest question, allowing language changes during a conversation. Cross-language vector retrieval requires the configured embedding provider; without vectors, bilingual aliases help common trading topics but are not full machine translation.

## AI provider and environment

When `AI_GATEWAY_API_KEY` or the Vercel-provided `VERCEL_OIDC_TOKEN` exists, chat generation uses the AI SDK Gateway and `CHAT_MODEL` (default `google/gemini-3.6-flash`). Otherwise it tries the existing loopback-only Ollama endpoint (`LOCAL_CHAT_URL`, default `http://127.0.0.1:11434/api/chat`; `LOCAL_CHAT_MODEL`, default `qwen2.5:7b`) and then grounded deterministic content. Remote Ollama URLs are rejected. Optional vector embeddings use `KNOWLEDGE_EMBEDDING_MODEL` (default `openai/text-embedding-3-small`) through AI Gateway. Gateway API keys must remain server-side and must never use a `NEXT_PUBLIC_` prefix. No provider credential is included in this repository.

`DATABASE_URL` enables persistent incremental documents/chunks/logs and unanswered-question review. Add it to `.env.local`, then apply the schema with `npm run db:push`. The chat endpoint checks source hashes on requests, so changed CMS records are synchronized on the next request; administrators may also run a protected manual sync at `/admin/knowledge`. Page-source changes are picked up when `knowledge:index` runs on dev/build/deployment. New public routes discovered by the indexer are included automatically. There is no always-running worker or external scheduler: chat-triggered sync is request-time work and a first full sync can be slower than subsequent incremental runs. For production, run the protected sync action or the indexing script during deployment to warm the index. Changes in static page source become current on the next build/deployment.

## Security and operations

The endpoint accepts only bounded text user/assistant messages; it discards client tool results, applies IP rate limits, and records sanitized unanswered questions only. Retrieved content and conversation history are treated as untrusted data, never system instructions. Tools call only existing controlled server queries. Account-specific information is not exposed by public chat. Admin synchronization and knowledge-gap review require the existing admin role. No full transcript is stored by sync or knowledge-gap features; contact data is redacted before gap storage.

To manually refresh the generated source corpus, run `npm run knowledge:index`. To persist/reconcile the current corpus immediately, an administrator can use `/admin/knowledge` → **Sync now**. Inspect last status, counts, and any sync error there. The endpoint also performs an incremental check during chat requests. If AI Gateway credentials are absent, content remains chunked and searchable lexically, and sync logs that embeddings are unavailable by recording empty vectors; supply the server credential and trigger sync to create vectors.

## Testing and limitations

Run `npm ci`, then `npm run test:knowledge-index`, `npm run test:question-understanding`, `npm run test:chat`, `npm run typecheck`, `npm run lint`, and `npm run build`. `npm run test:chat:http` exercises the local HTTP endpoint when the site is running. Persistent change propagation requires a configured Neon `DATABASE_URL`; semantic/cross-language vector retrieval additionally requires AI Gateway credentials and a supported embedding model. The checked-in unit tests cover source hashes and localization behavior but do not substitute for an actual database content-change sync test. Live provider and production database tests cannot be claimed unless those credentials are configured.

The coverage report separates the source-only scan from live database/feed data. Published FAQs, CMS edits, active instruments, news, quotes, and calendar events are loaded at request time; their live counts cannot be asserted by a build-only scan. User-specific account, KYC, and payout data is intentionally excluded from public chatbot retrieval.
